# ページの型と骨組み

1 ページは 1 つの型に属する。2 つの型が混ざったら、片方を正本のページへ移す。

## 共通の冒頭

どの型も、H1 の直後に次の 3 つを 2〜4 文で書く。

- このページが答える問い（誰が、何をしたいときに読むか）
- 一文での答え（推奨する選択、または結論）
- 読み終えてできること

`> **質問:**` のような引用ブロックの定型は使わない。普通の段落で書く。

## 手順（チュートリアルを含む）

読む人が手を動かして結果を得るページ。

```
# <動詞で終わる題>（例: 境界から粒子を流入させる）
冒頭（問い・答え・前提）
## 1. <操作>          … 最小の設定差分（新形式の TOML）とコマンド
## 2. <操作>
## 結果を確認する     … 期待する出力（実際の値や行）、それが示すこと
## この結果が示さないこと / 適用範囲
## 次に読むページ      … 5 件まで
```

- 設定は差分だけを示し、完全なファイルは `examples/` へリンクする。
- コマンドには前提と、成功したときに見える出力を書く。
- 選択肢が 3 つ以上あるときは、本文の前に比較表を置く。

## モデル

物理的な仮定と、BEACH がそれをどう計算に落とすかを説明するページ。

```
# <モデル名>
冒頭（何を表すモデルか、いつ使うか）
## 何を解くか          … 物理的な問題設定。式は最小限
## 仮定
## BEACH での扱い      … どの量をいつ計算し、粒子・表面電荷にどう効くか
## 設定                … 最小の新形式 TOML と、Parameters.md の該当節へのリンク
## 確認する出力        … 出力ファイル・列・判断基準
## 適用範囲            … 解かないもの、既知の制約（数値的な制約を含む）
```

- 全キーの一覧、既定値の表、内部の配列や MPI 集約は書かない（リファレンス・内部実装へ）。
- 他のモデルとの違いは、比較表 1 つか 2 文以内にする。

## リファレンス

調べるためのページ。読み物にしない。

- 見出しは検索される名前（キー、ファイル名、列名）にする。
- 定義・型・単位・既定値・制約を表で書く。背景の説明はモデルのページへリンクする。
- 網羅する。項目の順序は設定ファイル・出力ファイルの構造に合わせる。

## 内部実装

実装を変更・検証する人のためのページ。式、データの流れ、精度、Code reference を置いてよい。
利用者向けのページから内部実装を読まないと使えない状態にしない。

## 悪い例（このリポジトリで実際に起きたもの）

| 起きたこと | 直し方 |
|---|---|
| 機能を足すたびに節の末尾へ段落を継ぎ足し、光電子のページの 1 節が 90 行になった（閉じた光電子、固定電流、Zhao、障壁が 1 節に混在） | 節を、そのページが正本として持つ内容だけに書き直し、他は要約とリンクにする |
| 6 ページが、それぞれ上端の扱い（障壁、閉じた光電子、Zhao）を部分的に説明し直した | 比較は `PeriodicPlasmaSurface.md`、各方式の説明は各モデルのページだけに置く |
| 削除済みの入力（`[outer_plasma]`、`m2l_root_oracle` など）や非推奨の入力（`reservoir_face`）が、利用者向けの 8 ページに残った | 移行ページ（`GroupedConfiguration.md`）だけに置く |
| 新形式を推奨しながら、19 ページの設定例が旧形式のキーのままだった | 設定例は新形式だけにする。旧キーは対応表だけ |
| 妥当性確認のページに、削除済みのモデルの確認項目（外部モデルの grid 点数）が残った | 機能を消すときは、`grep` でその機能名を全ページから探して消す |
